This file captures technical decisions made for the project. The agent updates it at the end of each stage.

## Decisions Log

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Database | MySQL 8.0 (InnoDB) | Mandated by assignment spec |
| DB access pattern | SQLAlchemy Core + raw parameterized SQL | Spec-compliant; demonstrates SQL competence; no ORM overhead |
| DB driver | PyMySQL | Pure Python, no compilation needed |
| Auth | JWT HS256, 60-minute expiry | Standard, simple, spec-compliant |
| Password hashing | passlib bcrypt | Industry standard |
| RBAC mechanism | FastAPI dependency (`require_admin`) | Centralized, declarative, easy to audit |
| Embedding model | sentence-transformers `all-MiniLM-L6-v2` | 384-dim, CPU-friendly, ~80 MB, no GPU needed |
| Vector index | FAISS `IndexFlatL2` | Exact NN, fine at assignment scale (<1k docs) |
| Chunking | Whole-document, single vector | MVP scope; chunking is v2 |
| Activity logging trigger | Service-layer function call after success | Allows per-action payloads (vs middleware) |
| File storage | Local filesystem `backend/data/uploads/` | MVP; no S3 needed |
| Frontend bundler | Vite | Fast dev, modern defaults |
| Frontend language | TypeScript strict | Type safety, fewer runtime bugs |
| State management | React Context for auth; local state elsewhere | No Redux needed at this scale |
| CORS | Allow `http://localhost:5173` (Vite default) | Local dev only |

## AI Implementation Details

### Embedding Model
- `sentence-transformers/all-MiniLM-L6-v2`
- 384-dimensional vectors
- Downloaded once to `~/.cache/torch/sentence_transformers/` on first run
- Loaded into memory on FastAPI startup (lifespan hook)

### FAISS Index
- `IndexFlatL2` of dimension 384
- Persisted to `backend/data/faiss.index`
- Loaded on app startup if file exists, otherwise initialized fresh
- Saved to disk after every document upload

### Search Flow
1. Receive query string from `POST /search`.
2. Encode query: `model.encode([query], normalize_embeddings=False)` → `numpy.ndarray (1, 384)`.
3. Call `index.search(query_vec, top_k)` → returns `(distances, ids)`.
4. Look up `documents` rows where `vector_id IN (...)`.
5. Build response with `document_id`, `title`, `snippet` (first 280 chars), `score` (L2 distance, lower = better).
6. Log activity with action `search` and `payload={"query": ..., "top_k": ...}`.

## Activity Logging

Implemented as a single utility in `app/utils/activity.py`:

```python
def log_activity(conn, user_id: int, action: str, payload: dict | None = None) -> None:
    conn.execute(
        text("""
            INSERT INTO activity_logs (user_id, action, payload)
            VALUES (:uid, :action, :payload)
        """),
        {"uid": user_id, "action": action,
         "payload": json.dumps(payload) if payload else None}
    )
```

Called from service methods after the primary operation succeeds. Wrapped in `try/except` so a logging failure never blocks the user-facing operation.
